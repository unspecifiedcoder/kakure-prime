# Kakure — Shielded FROST-Multisig Treasury on Solana

**Status:** approved design, v1 scope
**Date:** 2026-09-05
**Origin:** port of the reference EVM implementation's FROST-multisig shielded-note system (EVM, Noir/UltraHonk) to Solana (Noir → Groth16 via Sunspot).

## 1. Product

One line: *Squads, but the chain cannot tell it is a multisig.*

A DAO or on-chain fund creates a t-of-n FROST signing group (dealerless DKG), deposits SPL tokens into a shielded pool, and moves funds with FROST-signed zero-knowledge proofs. On-chain there are only note commitments, nullifiers, encrypted payloads and proofs. Invisible on-chain: the signer set, the threshold, balances, recipients, and the fact that a multisig exists at all. An auditor committee key (threshold ECDH, already built into every circuit) gives selective disclosure for compliance without a single trusted party.

Nothing with these properties exists on Solana today (Squads and every other multisig is fully transparent; Arcium/Darklake/Light/Hinkal/NOCtura do private transfers or trading, none do private group custody).

### v1 scope (in)

- Circuits: `deposit`, `transfer`, `withdraw` (single-key) and `transfer_multisig`, `split_multisig`, `join_multisig`, `withdraw_multisig` (group). Single-key `transfer`/`withdraw` exist so that recipients paid by a treasury can move or exit funds.
- One Solana program (`kakure_pool`) holding the commitment tree, nullifiers, SPL vaults, compliance key and verifier registry.
- Groth16 verifier programs generated by Sunspot, one per circuit, called by CPI.
- TypeScript SDK (ported from `the reference EVM implementation's wallets package`), local prover, coordinator relay, indexer, CLI, read-only dashboard.
- Localnet end-to-end test: DKG → deposit → 3-of-5 transfer → recipient withdraw.

### v1 scope (out)

- Swaps (Kage circuits use Noir recursion; no Groth16 equivalent here).
- PSS backup service, Howl single-shot discovery, public memos/`public_claim`, `split`/`join` for single-key notes.
- Browser-side proving (gnark→WASM) — v2.
- Mainnet trusted-setup ceremony execution (scripted, not run, in v1).

## 2. Proof stack

| Layer | Choice | Notes |
|---|---|---|
| Circuit language | Noir 1.0.0-beta.22 | Same pin as the reference EVM implementation CI and as Sunspot's requirement. |
| Circuit sources | vendored copies of `shared/`, `vendor/{ecdh,noir-edwards,poseidon}`, the 7 v1 crates, their mutation tests | Copied, not submoduled; provenance file lists the reference EVM implementation's commit `3e7333c`. |
| Proof system | Groth16 over BN254 via Sunspot (`compile → setup → prove → verify → deploy`) | Unaudited toolchain; Apache-2.0. |
| Witness generation | `@noir-lang/noir_js` (produces the gzipped witness stack Sunspot expects) | Runs in Node; the witness never leaves the signer's machine. |
| Proving | `sunspot prove` (gnark, Go binary) invoked by the CLI | Local only. A hosted prover would see balances — rejected. |
| On-chain verify | Sunspot-generated verifier program per circuit (`verifier-bin` with VK baked in), invoked by CPI from `kakure_pool` | 170k–500k CU, proof 324–388 bytes. |
| Trusted setup | dev: `sunspot setup` (insecure, labelled); release: `reilabs/trusted-setup` MPC script | VK hashes pinned in a manifest and drift-tested. |

Why CPI rather than embedding `gnark-verifier-solana` in the pool program: it is the exact path Sunspot supports and tests, keeps the pool program free of the verifier crate's `solana-program` version constraints, and lets a verifier be replaced by governance (`set_verifier`) without redeploying the pool. Embedding is a later optimisation.

## 3. Cryptographic changes from the reference EVM implementation

Everything below is a deliberate divergence from the EVM system. Nothing else in `shared/` changes.

1. **Merkle tree hash: Poseidon2 → Poseidon (v1, circom parameters).** The tree is a LeanIMT: `node = H(left, right, level)`, zero sibling passes through, canonical-index assert. The pool program must recompute this on every insert; Solana's `sol_poseidon` syscall is Poseidon v1 on BN254 (circom-compatible, ≤12 inputs), while hand-rolled Poseidon2 in SBF would exceed the compute budget. Change `lean_imt_inclusion_proof` in `shared/src/lib.nr` to `poseidon::bn254::hash_3([left, right, level])`, and the TS `LeanIMT` to the matching circom Poseidon. Note commitments, `psi`, nullifiers, owner hashes, FROST challenge, DEM/KEM all stay Poseidon2 (never computed on-chain).
2. **`asset_id` = first 20 bytes of `sha256("kakure.asset.v1" ‖ mint_pubkey)`**, big-endian into a Field. Circuits already assert `asset_id` fits 20 bytes; unchanged. The pool keeps an `Asset` PDA per `asset_id` recording the mint, created on first deposit; a second mint mapping to an existing `asset_id` is rejected (`AssetCollision`).
3. **`recipient` (withdraw) = `sha256("kakure.recipient.v1" ‖ destination_token_account) ` with the top byte zeroed**, so it is < the BN254 scalar field. The pool recomputes it from the destination account passed in the instruction and requires equality with the public input. Multisig withdraw binds it into the FROST message; single-key withdraw binds it only on-chain (same as the reference EVM implementation).
4. **`intent_hash` = 0** in v1 (no adaptors). The pool requires it to be 0.
5. **Genesis leaf** seeded per cluster: `genesisLeaf(genesis_hash_of_cluster)` replacing `genesisLeaf(chainId)`.
6. **Root history: ring buffer of 256 roots** instead of the reference EVM implementation's unbounded `isKnownRoot` map. A proof against an evicted root is rejected (`StaleRoot`); the client re-proves. 256 roots ≈ 256 inserts of headroom, adequate for v1 throughput; sized as a constant.

## 4. On-chain program: `kakure_pool`

Framework: Anchor (latest 0.31+/0.32, installed via `avm`); fall back to a native `solana-program` crate if Anchor cannot target the installed Agave 3.0 toolchain. Program is upgradeable with an `authority` (multisig later).

### Accounts

- `Pool` (singleton PDA `["pool"]`): `authority`, `compliance_pk_x/y` (32 B each), `compliance_version`, `verifiers: [Pubkey; 7]` indexed by `CircuitId`, `next_leaf_index: u64`, `side_nodes: [[u8;32]; 32]`, `roots: [[u8;32]; 256]`, `root_cursor: u8`, `paused: bool`.
- `Asset` (PDA `["asset", asset_id(20)]`): `mint`, `vault` (token account owned by the pool PDA), `asset_id`.
- `Nullifier` (PDA `["nullifier", nullifier(32)]`): zero-size marker; existence = spent. Created with `init` so a second creation fails atomically.
- `NoteEvent` emitted via `emit_cpi!` (self-CPI, survives log truncation): `leaf_index, leaf, eph_pub_x, tag?, cek_wrap?, ciphertext[7]`.

### Instructions

| ix | public inputs (count) | checks |
|---|---|---|
| `initialize(compliance_pk, verifiers)` | — | authority signer |
| `set_verifier(circuit_id, program)` / `rotate_compliance_key(x,y)` / `set_paused` | — | authority signer; rotation bumps `compliance_version`, emits event |
| `deposit(proof, inputs, amount)` | 13 | `inputs[2] == amount`, `inputs[3] == asset_id(mint)`, compliance key exact match, verify via CPI, `transfer_checked` amount into vault (mint must not be a fee/transfer-hook mint — reject Token-2022 extensions except none), insert leaf, emit |
| `transfer(proof, inputs)` / `transfer_multisig` | 24 | compliance, root ∈ ring, nullifier unused → create PDA, verify, insert memo leaf and change leaf, emit both |
| `split_multisig(proof, inputs)` | 22 | as transfer; two output leaves |
| `join_multisig(proof, inputs)` | 14 | compliance, root, two nullifiers (both PDAs created), verify, insert one leaf |
| `withdraw(proof, inputs, amount)` / `withdraw_multisig` | 17 | `inputs[0] == amount`, `inputs[1] == recipient_field(dest)`, `inputs[2] == 0`, compliance, root, nullifier, verify, insert change leaf, `transfer_checked` from vault to `dest` |

Public-input layouts and indices are copied verbatim from the reference EVM implementation's circuit ABIs and locked by a test that parses the compiled ABI JSON.

Compute budget per tx: verifier CPI (≤500k) + ≤2 leaf inserts × 32 `sol_poseidon` calls (~4–6k each worst case) + account ops. Clients attach a `ComputeBudget` ix requesting 1.4M CU.

### Insert algorithm

Frontier insert identical to `MerkleTreeLib.sol`: walk levels 0..32; even index stores `side_nodes[level] = node` and stops; odd index hashes `node = H(side_nodes[level], node, level)`; then `next_leaf_index += 1`, push root into the ring. Leaf `0` rejected.

## 5. Off-chain components (TypeScript, pnpm monorepo)

```
kakure/
  circuits/                 Noir workspace (vendored from the reference EVM implementation) + Sunspot build scripts
  programs/kakure_pool/     Anchor program
  packages/sdk/             ported wallets: keys, notes, LeanIMT, FROST, DKG, threshold, tx planning; Solana adapter (chain view, tx builder, ABI layouts)
  packages/prover/          noir_js witness + sunspot prove wrapper; proof/public-input marshalling
  packages/indexer/         watches NoteEvents, maintains LeanIMT mirror, serves ciphertexts, Merkle paths, roots, compliance key history (HTTP + WS)
  packages/coordinator/     E2E-encrypted relay for DKG rounds, spend proposals and FROST round-1/round-2 messages
  packages/cli/             kakure group create|join, deposit, propose, sign, execute, balance, withdraw
  apps/dashboard/           read-only web UI: decrypts with view key in-browser, shows balances/history
  e2e/                      localnet end-to-end tests
```

### SDK port rules

- Copy `frost/`, `tss/`, `threshold/`, `note/`, `merkle/LeanIMT.ts`, `discovery/`, `tx/plan.ts`, `tx/assemble.ts` unchanged except the tree hash.
- Replace the seven EVM-coupled files (`crypto/fields.ts`, `merkle/genesis.ts`, `keys/DarkAccount.ts`, `public/*`, `sync/PublicMemoScanner.ts`, `sync/ScanEngine.ts`, `tx/ports.ts`) with Solana equivalents; drop `public/*`.
- Keep the KATs (known-answer tests) from the reference EVM implementation for everything Poseidon2-based; regenerate tree KATs.

### Coordinator privacy contract

The coordinator relays only ciphertext addressed to a group session id. Group members derive a shared session key from the DKG output (`deriveGroupViewKey`); proposals, nonce commitments and signature shares are encrypted end-to-end. The coordinator learns: session ids, message sizes, timing. It never learns group public keys, amounts, recipients or membership. It must not log `(session_id, timestamp)` pairs together (same rule as the reference EVM implementation's PSS runbook).

### Prover

`prove(circuitId, inputs)`: build the Noir `InputMap` (marshalling copied from `the reference EVM implementation/packages/prover/src/marshal.ts`), execute with `noir_js` to get the witness, write `witness.gz`, run `sunspot prove <circuit>.json witness.gz <circuit>.ccs <circuit>.pk`, parse `.proof` and `.pw`, return `{ proof: Uint8Array, publicInputs: Field[] }` in the order the pool expects. Self-verify with `sunspot verify` before returning.

## 6. Trust and security notes

- Soundness is circuit-centric: the pool has no `msg.sender`-style authorisation on money paths; only proofs, nullifiers and roots gate funds. Mutation tests from the reference EVM implementation are carried over and must pass.
- Groth16 introduces per-circuit toxic waste. Dev keys are marked `INSECURE-DEV` in the manifest; a release build refuses to deploy verifiers built from dev keys.
- Sunspot is unaudited. The verifier programs are reproducible: CI rebuilds them from pinned VKs and compares hashes.
- Deposit correctness of `owner` is the depositor's responsibility (as in the reference EVM implementation): a wrong owner burns the deposit.
- Nullifier PDAs cost rent (~0.001 SOL each); acceptable for treasury-scale usage.

## 7. Testing

- **Circuits:** all the reference EVM implementation Noir tests + mutation tests pass on beta.22; new KAT for Poseidon-v1 tree paths shared with TS and Rust.
- **Program:** `litesvm` tests — happy paths for all 7 ixs; invalid proof; double spend; stale root; wrong compliance key; amount/asset mismatch; recipient mismatch; asset collision; pause. Frontier-insert KAT vs TS `LeanIMT`.
- **SDK/prover:** ported unit tests; a `publicInputLayout` test that asserts flat counts from the compiled ABIs equal the program's expected counts.
- **Coordinator/indexer:** unit tests plus a privacy-log test (no `(session_id, timestamp)` in logs).
- **E2E (localnet, `solana-test-validator`):** deploy pool + 7 verifiers; 5 signers run DKG; deposit USDC-like mint; 3-of-5 transfer to a single-key recipient; recipient withdraws; a 4th signer's late share is rejected; a replayed nullifier fails.
